Website and app data

Privacy

Updated 4 November 2026. This page describes this static website and the app behavior documented in the current user manual.

This website

The website's pages contain no analytics scripts, advertising, embedded donation widgets, account system or submission forms. The site code does not set cookies or use browser local storage. Images and stylesheets are served with the site rather than loaded from third-party font or image services.

Hosting services can still process request information such as your IP address and browser details to deliver and protect the website. This site's deployment is configured for GitHub Pages; see the GitHub General Privacy Statement for GitHub's handling of personal data. The absence of analytics in the site code is not a promise that the hosting provider keeps no logs.

External links and donations

Links to GitHub and Ko-fi take you to services with their own privacy practices. Ko-fi handles optional donations; this website has no payment form and does not receive payment-card details through its pages. Review the external service's privacy information and terms before submitting information or contributing.

Android app permissions and connections

The experimental app uses phone sensors to estimate attitude. Optional GPS displays need precise-location permission and device location enabled; Bluetooth on newer Android versions needs Nearby devices permission. Android 13 and later request notification permission for service notifications.

The manual states that the app does not request background-location permission. GPS requests may nevertheless continue while another app is visible if GPS displays are enabled. Disable both GPS ground speed and GPS altitude, or stop the service, to stop those requests.

The optional XCSoar feed sends bank and pitch only to the configured destination. Local mode uses the same phone; Wi-Fi mode sends to a trusted local network; Bluetooth uses a paired device. LAN UDP is not encrypted or authenticated. See connection setup before enabling transmission.

Recordings and exported files

Recording is explicitly started in Diagnostics. Captures contain sensor, attitude, calibration and diagnostic data, including mounting metadata and gain changes. The current manual says optional GPS/pressure tape values and flight level are not recorded.

Recordings remain app-private until explicitly exported through Android's document picker. After export, the chosen destination controls access to that copy. Review files before sharing them, particularly mounting descriptions and diagnostic metadata.

Delete private captures through Recordings. Uninstalling or clearing app storage erases private recordings, settings and calibration, but does not remove copies already exported elsewhere. Exporting a recording does not back up all app settings.

Support and scope

Use the support channel supplied with your build for app or app-data questions. Do not include personal notifications, private recordings or unrelated personal data in public feedback. See support guidance.

App details here summarize the 4 November 2026 manual, not an independent audit of every build. Consult the privacy information and terms accompanying your installed release for build-specific behavior.
